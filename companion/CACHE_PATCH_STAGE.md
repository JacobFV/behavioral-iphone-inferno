# Fresh renderer cache patch stage

`stage-cache-patch.py --help` describes the fixed producer. It consumes a successful typed `flattened-keybag.json`, a separate successful read-only `runtime-inspection.json` from the **same keybag predecessor**, the reproducible owned helper build, original/patched cache files and original-byte sidecar, all with explicit SHA256s. Neither an inspection descendant nor a failed installed boot is used as backing. Output must be a new external directory.

Before allocation it replays the fresh keybag/growth chain, normal raw shutdown and original API proof; checks flatten source preservation, actual convert/compare records, GPT and full raw hash; and validates the inspection's original full dyld hash, serial export, normal finish, frozen seven-file tuple and predecessor. The flattened raw and exact six initialized auxiliary references are retained unchanged. At least 2 GiB free is required for this sparse child, prepared recovery and logs; creating the earlier raw still separately requires 34 GiB.

The unchanged `fs-patches/make-plan.py` streams existing original/patched files to regenerate the fixed plan, proving all unlisted bytes equal. It creates only the 1104-byte plan, not another cache copy. Required original/patched hashes, upstream revision, 45 records and 180 replacement bytes are fixed in `cache_patch_stage.py`. Upstream InfernoFSPatcher attribution and its AGPL license remain in `fs-patches/README.md`.

The unchanged preparation path installs only the reviewed helper, plan and digest pair into a fresh recovery image. The coordinator independently extracts and verifies helper/probe/job/plan/digests. No launchd-cache or runtime helper changes are combined with the renderer patch.

The guest must emit ordered original-cache full SHA, validation of all 45 records, patched-cache full SHA, original clean unmount and result0. The unchanged helper performs old-byte validation, pwrite, fsync and replacement-byte readback. Missing/duplicate/out-of-order/failure records fail closed. Only after saving the exact raw prefix checkpoint does the coordinator send its sole `finish-observation`. Normal report/QMP/PID checks, full seven-file hashes, new-only freezing, ordinary retention and unchanged ancestor verification precede publication.

The result is `renderer-cache.json`, schema `inferno.renderer-cache-stage.v1`, status `renderer-patched-not-runtime-ready`, depth2, and `ipa_runtime_ready:false`. It contains typed flattened predecessor and inspection references, actual content proof, plan provenance, source/input/raw evidence hashes and stopped report/retention hashes. This establishes a cache-patch stage, not an installed boot or IPA interaction. No actual fresh execution is claimed until these input results exist and the coordinator completes. All cache/firmware/plan bytes remain outside Git.
