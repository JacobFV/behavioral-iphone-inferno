# Strict journey followed by a new owned process

The old verifier rejects actual38 with `main raw record: expected one, got 2`. The new verifier first pairs every relevant raw event with its exact boot/PID/sequence validation and one nearby marker. Unpaired markers and multiply paired markers fail. It then selects exactly one strict chain using verified arrival chronology. Other records must be later than strict completion, share the boot, and use another PID. Same-PID duplicate events remain failures. Original source-pinned capture gates, exact single intervening tap, input wire/ACK, capture hashes and normal shutdown checks remain intact.

For runs without recorded arrival observations, the old global uniqueness rule remains unless the operator independently retains a completed strict serial prefix **before** subsequent OPEN creation. `--strict-prefix` accepts its explicit manifest: absolute `serial_prefix_path`, `serial_prefix_bytes`, `serial_prefix_sha256`, `read_started_host_epoch`, `captured_host_epoch`. The verifier requires byte-identical final-log prefix, complete lines, read start after actual after-capture QMP reply and capture time before all subsequent OPEN requests' recorded creation times. Every later lifecycle record must begin outside that prefix. This is a host checkpoint, not a reconstructed guest timestamp. No historical checkpoint is invented for38.

It never mutates actual reports. Actual38 passes with its original arrival records;55 passes without needing a prefix. The prefix route awaits the parent's genuinely new checkpoint in56 and subsequent final run evidence.
