# ADP completion audit and next discriminating diagnostic

Actual captured windows in failed44/47 and healthy49/53/57 contain respectively5/5/12/42/14 complete ordered chains: submit → BH enter → BH exit → guest W1C clearing an actually set FRAME_PROCESSED bit. There is no second traced submit before that clearing in any chain. The last completed chain in each failed run is also acknowledged. This is stronger than equal totals: `audit.py` checks order and before/after status values, retaining raw byte/line references and selected trace lines. It covers only enabled windows.

This does not support a lost pending draw, coalesced submitted BH, or unacknowledged FRAME_PROCESSED bit *inside these windows*. The generic QEMU BH queue can coalesce schedules while pending, but that possibility was not exercised in these traces. A preceding untraced transition remains unknown. Repeated OUTPUT_READY while already latched occurs in both groups (44:8,47:7,49:3,53:4,57:4); it is not a failure-specific signal.

The model has one bit per ready/processed condition, not a queued completion count. `gfx_update` ORs OUTPUT_READY; submit bit12 schedules the guarded BH; the BH draws both pipes and ORs FRAME_PROCESSED regardless of per-pipe outcome. W1C atomically clears requested bits. Every update recomputes IRQ0 from `int_enable & int_status`. The board connects display IRQ outputs to original DT AIC inputs. AIC input records level; a64us virtual timer runs delivery selection. Original AIC IACK masks the selected input, and guest mask-clear reenables it. This source chain contains additional state beyond the current ADP trace.

## Minimal next diagnostic, proposed only

Add one opt-in metadata trace for **known main INT_STATUS reads at0x45818**, recording the exact value already returned and the normalized offset. It must not perform another MMIO read, alter state, acknowledge an interrupt or change timing policy. Current unknown-MMIO tracing deliberately excludes this known register, so the logs show writes clearing bits but not what status the original driver read. An existing HMP register query goes through the same read function: avoid `query-display-registers` during the short window, or explicitly identify the fixed query in QMP provenance; do not automatically call every trace read a guest read.

Use the existing fixed-event sole-runner trace window, initially10seconds, with byte checkpoints and actual automatic disable evidence. Existing ready/processed/submit traces plus exact status-return values can distinguish: (1) no status reads despite newly asserted status, suggesting a delivery or service boundary; (2) reads seeing ready/processed followed by matching W1C but no submissions, moving the missing work beyond driver acknowledgement; (3) reads already zero or mixed bits, exposing a different read/clear sequence for original-driver inspection. None alone proves userland notification delivery or causality. Volume is unknown until measured because driver polling could be frequent; retain a short10s trial rather than assume a low event rate.

Broader AIC hooks are **not the first choice**. Existing `aic_set_irq` traces every external input, cannot filter one display source and omits actual IACK/mask-clear correspondence. A meaningful second-stage trace would need the exact original DT display IRQ mapping and narrowly filtered input-level/IACK/mask-clear records. Never use a diagnostic read of IACK: it consumes interrupt state. Current periodic ready/W1C traffic already makes a blanket AIC-delivery failure unlikely, but does not prove the original higher-level frame/fence callback completed.

If status reads confirm normal matching read/clear sequences while the app and Home background events remain responsive, the remaining useful discriminator is an original backboardd/SpringBoard sample taken **during the stalled state**, compared with healthy49. Only healthy samples exist so far. The source audit does not justify changing IRQ, frame-completion, BH or guest compositor behavior.

No emulator, guest, tooling or runtime behavior was changed for this audit. No inputs, queries or VMs were initiated.
