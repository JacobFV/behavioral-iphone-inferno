# Fresh owned runtime installation: plan only

No implementation, guest action, large copy or full image hash in this review. Current fresh lineage ends at original SEP/keybag initialization, not app readiness.

## Minimal ordered milestones

1. Consume the typed, verified keybag flatten result with its six paired auxiliary states. Diskworker's new fixed read-only inspector must supply this lineage's actual original launchd configuration export and exact full dyld cache hash. Do not substitute install31 or a historical descendant's cache identity. Inspector scope and normal stopped provenance must be verified independently.
2. Bind a new renderer patch plan to the freshly observed original dyld-cache hash. Reuse reviewed existing patch generator/application only after their exact original input, output and records are pinned. Require actual guest full before/after cache hashes, exact approved sparse records, clean unmount and normal seven-namespace retention. This is separate from launchd configuration. No new graphics behavior fix is proposed.
3. Produce exact owned runtime artifacts outside Git: preparation helper via build-prepare-helper.py; observer/readiness, HID and one fresh-VM empty-secret helper via reviewed source and original import/entitlement audit; optional fixture app/launcher/wrapper via app-probe producers. Legacy native-probe/build.sh currently links prepare-root.o alone despite install_imported_app now being external, so a fresh all-artifact build is not yet proven reusable. Either use exact reviewed retained artifact pins with honest provenance or make a narrowly scoped reproducible producer; no implicit new entitlement.
4. Merge NEW owned jobs into the newly exported launchd cache using merge-launchd-cache.py --cache ... --job ...; preserve every original entry. --replace-owned-job requires an actually existing unique owned label and is inappropriate for first insertion. Historical owned labels are org.inferno.readiness, org.inferno.unlock-empty, org.inferno.app-probe. Readiness is root RunAtLoad with console output and no KeepAlive; it starts the bounded event/HID children, no gestures. Empty-secret job historically root RunAtLoad/KeepAlive=false; this is only for the proven fresh simulated no-passcode state. App job invokes /usr/bin/inferno-exec-launcher --system-app as root; wrapper performs the actual mobile drop. The app job has KeepAlive SuccessfulExit=false and throttle30, so its restart semantics must be explicit, not described as one-shot. A generic manifest-bound launcher remains distinct from fixture telemetry.
5. Stage only explicit existing helper operations: --disk-helper-existing plus --readiness-probe, --hid-input-helper, --unlock-helper, --exec-wrapper, --system-launcher, --launchd-cache/--launchd-cache-sha256, and optional --system-app-dir for the owned fixture. This maps to --install-readiness/--install-hid-input/--install-unlock-helper/--install-exec-wrapper/--install-system-launcher/--install-cache/--install-system-app. Do not repeat seed/keybag/roles. HFS readback must match each input/job/cache; actual guest readback byte totals derive from exact artifacts, not copied historical numbers. Require each relevant *_READBACK mismatches=0, complete operation order, clean System unmounts, PREP_COMPLETE, checkpoint-before-one-finish, QMP normal shutdown and frozen seven-file ancestry.
6. Installed boot explicitly uses --disk-boot --launchd-unsecure-cache, which adds original supported bootarg launchd_unsecure_cache=1. The configuration installer writes only /System/Library/xpc/launchd.plist; original .sig remains unchanged. No signature generation, forged identity or substitute verification assertion. Optional --disable-unsupported-services alters five documented original Disabled flags; choose and record explicitly, never silently infer it from historical cache.
7. Actual original migration, first unlock and ordinary Setup remain required. Observe original MKB/SEP transitions, services and visible Setup/Home state; no fabricated migration/notification/setup files. Setup screens may vary. Normal post-setup boot, original registration/launch and reviewed owned UI should establish runtime viability separately from installation. Existing display freeze remains unresolved; one successful boot is not a reliability guarantee.

## Future prepare-import contract

Keep existing inferno.local-ipa-runtime.v1 retained-lineage branch unchanged. Add a separately versioned fresh-lineage branch only after concrete inspector/renderer/install/installed-run schemas exist. Require exact typed predecessor hashes and raw-content verifiers, fresh exported-cache hash, deterministic merge preserving original entries, HFS and guest cache/artifact readbacks, normal stopped reports/source pins, exact auxiliary lineage and sufficient depth for recovery plus installed child. Successful flatten must carry explicit logical-compare provenance rather than invented boot ancestry. Pin untouched original .sig identity if inspector supports it; source code's nonmutation alone is weaker than observed identity.

The new branch must not accept basis=reviewed-retained-lineage-not-fresh-guest-export with install31 references for this root, nor treat a cache size marker as cache identity. Current prepare-import also rechecks legacy binding fields late in main (lines155–156), so schema handling must be centralized and used both initially and immediately before publication. The current import producer replaces an existing org.inferno.app-probe cache job: a fresh runtime must truthfully contain that job, or a separately reviewed add-versus-replace contract is needed. Do not install a dangling placeholder job merely to satisfy the old importer.

Resource constraint: roughly19GiB host free means no unplanned complete disk/cache duplicates. Full cache hashing may read without export; target-specific cache export/patch strategy and each new backing's allocation must be reviewed before action. This plan creates no IPA-ready manifest.
